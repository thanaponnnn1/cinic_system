# แผนทดสอบด้วยมือ — THNP ClinicQ

ไล่ทดสอบทุกฟีเจอร์ที่ทำมาตั้งแต่ Phase 1 ถึง Phase 7 ด้วยมือจริง ก่อนขึ้นระบบให้ลูกค้าใช้

ทำตามลำดับได้เลย ข้อที่ต้องใช้ LINE จริงมีเครื่องหมาย 📱 กำกับไว้ ถ้ายังไม่อยากยิงข้อความออกไป
ให้ข้ามข้อพวกนั้นไปก่อน แล้วดูผลจากหน้า **ข้อความที่ส่ง** แทน ซึ่งบันทึกทุกครั้งที่ระบบตัดสินใจ
ว่าจะส่งหรือไม่ส่ง ไม่ใช่เฉพาะตอนส่งสำเร็จ

## 0. เตรียมก่อนเริ่ม

### สิ่งที่ต้องรันอยู่

| อะไร | คำสั่ง | ตรวจว่าขึ้นแล้วยังไง |
| ---- | ------ | -------------------- |
| ฐานข้อมูล + Redis | `pnpm db:up` | `docker ps` เห็นสองคอนเทนเนอร์ |
| API + หน้าเว็บ + shared | `pnpm dev` | เปิด http://localhost:3001/health เห็น `{"status":"ok"}` |
| worker | `pnpm --filter @clinicq/backend worker` | ล็อกขึ้น `worker พร้อมรับงานจากคิว "reminders"` |
| อุโมงค์ LINE (เฉพาะข้อ 📱) | `ngrok http 3001` | เอา URL ไปตั้งใน LINE Developers Console → Webhook URL = `<ngrok>/api/webhooks/line` |

> **ห้ามรัน `worker:dev` คู่กับ `pnpm dev`** — ทั้งคู่เป็น `nest start --watch` ซึ่งลบ `backend/dist`
> ทิ้งทั้งโฟลเดอร์ก่อนคอมไพล์ สองตัวจะลบไฟล์ของกันและกันจน API ตายด้วย `Cannot find module`

### หน้าจอที่จะใช้ระหว่างทดสอบ

- **http://localhost:3000** — dashboard
- **http://localhost:3001/docs** — Swagger ไว้ยิง API ตรง ๆ ตอนอยากดูข้อมูลดิบ
- **http://localhost:3001/admin/queues** — คิวงาน (ผู้ใช้/รหัสตาม `BULL_BOARD_USER` / `BULL_BOARD_PASSWORD` ใน `backend/.env`)
- **`pnpm db:studio`** — เปิดตารางในฐานข้อมูลดูตรง ๆ ตอนอยากพิสูจน์ว่าข้อมูลถูกเขียนจริง

### บัญชีทดสอบ

รหัสผ่านเดียวกันทุกบัญชี: `demo1234`

| อีเมล | สิทธิ์ | ใช้ทดสอบอะไร |
| ----- | ------ | ------------ |
| `owner@thnpclinic.com` | ADMIN | ทุกอย่าง |
| `staff@thnpclinic.com` | STAFF | งานหน้าร้าน แต่แก้ช่าง/บริการ/แคมเปญไม่ได้ |
| `demo@thnpclinic.com` | VIEWER | ต้องไม่เห็นเบอร์โทร ประวัติ และหน้าข้อความ |

### ข้อควรรู้เรื่องข้อมูลตัวอย่าง

- **สมหญิง ใจดี (0810000001) ผูกกับบัญชี LINE ของคุณอยู่** ทุกข้อความที่ระบบส่งหาคนนี้จะเด้งเข้ามือถือคุณจริง
- ลูกค้าอีก 12 คนที่ "ผูก LINE แล้ว" ใช้ `lineUserId` ปลอม — ส่งไปจะได้ผล **ส่งไม่สำเร็จ** ซึ่งถูกต้องแล้ว ไม่ใช่บั๊ก
- อยากเริ่มใหม่ทั้งหมด: `pnpm db:reset && pnpm db:migrate && pnpm db:seed` (ล้างฐานข้อมูลทิ้งทั้งหมด)
- อยากแค่เติมข้อมูลตัวอย่างกลับ: `pnpm db:seed` (ไม่ลบของเดิม ไม่ทับรหัสผ่าน)

### ปุ่มข้ามเวลา

แผงมุมซ้ายล่างของ dashboard (โผล่เฉพาะตอน `DEMO_MODE=true`) ทำสองอย่างพร้อมกัน:
ขยับเวลาที่ทั้งระบบมองเห็น และดันงานในคิวที่ถึงกำหนดตามเวลาใหม่ให้ทำงานทันที

**ข้ามแล้วอย่าลืมกด "กลับมาเวลาจริง"** ก่อนเริ่มทดสอบหัวข้อถัดไป ไม่งั้นผลที่เห็นจะแยกไม่ออกว่า
มาจากสิ่งที่เพิ่งกดหรือจากเวลาที่ค้างอยู่

## 2. เข้าสู่ระบบ สิทธิ์ และ PDPA

- [ ] **2.1** ใส่รหัสผ่านผิด → ขึ้นข้อความ "อีเมลหรือรหัสผ่านไม่ถูกต้อง" ไม่ใช่หน้าจอ error ดิบ
- [ ] **2.2** เข้าสู่ระบบสำเร็จแล้วเปิด DevTools → Application → Cookies → เห็น `clinicq_access` และ `clinicq_refresh` ทั้งคู่ติดธง **HttpOnly**
- [ ] **2.3** ใน Console พิมพ์ `document.cookie` → **ต้องไม่เห็น token ทั้งสองใบ** (นี่คือจุดที่ต่างจากการเก็บใน localStorage)
- [ ] **2.4** ลบ cookie `clinicq_refresh` ทิ้งแล้วกดรีเฟรชหน้า → ถูกพากลับไปหน้าเข้าสู่ระบบ
- [ ] **2.5** เข้าสู่ระบบใหม่ แล้วลบเฉพาะ `clinicq_access` (เก็บ `clinicq_refresh` ไว้) → กดสลับหน้าไปมา ต้องใช้งานได้ปกติ และ cookie `clinicq_access` ใบใหม่โผล่กลับมาเอง
- [ ] **2.6** กด **ออกจากระบบ** → กลับไปหน้าเข้าสู่ระบบ กดปุ่ม Back ของเบราว์เซอร์ก็ต้องไม่กลับเข้าไปได้
- [ ] **2.7** เข้าด้วย `demo@thnpclinic.com` (VIEWER) → เมนู **ข้อความที่ส่ง** ต้องหายไปจากแถบซ้าย
- [ ] **2.8** ยัง VIEWER อยู่ พิมพ์ URL `/messages` ตรง ๆ → หน้าจอขึ้นข้อความว่าไม่มีสิทธิ์ ไม่ใช่ตารางข้อมูล
- [ ] **2.9** ยัง VIEWER อยู่ เปิดหน้า **ลูกค้า** → ช่องเบอร์โทรเป็น `—` ทุกแถว และไม่มีปุ่มเพิ่มลูกค้า
- [ ] **2.10** ยัง VIEWER อยู่ เปิดรายละเอียดลูกค้า → toggle ความยินยอมกดไม่ได้ (จางลง)
- [ ] **2.11** เข้าด้วย `staff@thnpclinic.com` → เห็นเบอร์โทรครบ ทำงานหน้าร้านได้ทุกอย่าง

> **จุดสำคัญ**: VIEWER ไม่ได้ถูก "ซ่อน" เบอร์โทรที่หน้าจอ แต่ API ไม่ส่งฟิลด์นั้นออกมาตั้งแต่แรก
> ตรวจได้ที่ Swagger → เข้าสู่ระบบด้วย VIEWER แล้วเรียก `GET /api/customers` จะเห็นว่า JSON ไม่มีคีย์ `phone` เลย

## 3. ข้อมูลฐาน

- [ ] **3.1** หน้า **ลูกค้า** → กด **เพิ่มลูกค้า** ใส่ชื่อและเบอร์ 10 หลัก ติ๊กยินยอมทั้งสองชนิด → บันทึกได้ และแถวใหม่โผล่ในตาราง

## 4. นัดหมาย

- [ ] **4.1** จองคิว: เลือกช่างและบริการก่อน → รายการเวลาต้องขึ้นเฉพาะช่องที่ว่างจริงและยาวพอสำหรับบริการนั้น
- [ ] **4.2** เลือกบริการที่ยาวกว่า (เช่น ทรีตเมนต์บำรุงผม 90 นาที) → จำนวนช่องเวลาที่เลือกได้ต้องน้อยลง
- [ ] **4.3** **กันจองซ้อน**: เปิดหน้าจอสองแท็บ จองช่างคนเดียวกันเวลาเดียวกันพร้อมกัน → แท็บที่สองต้องขึ้น "ช่วงเวลานี้ถูกจองไปแล้ว" พร้อมบอกว่าใครจองอยู่ ไม่ใช่จองซ้อนสำเร็จทั้งคู่
- [ ] **4.4** บนการ์ดคิว กด **ยืนยันแทนลูกค้า** → ป้ายเปลี่ยนเป็น "ยืนยันแล้ว" สีเขียว
- [ ] **4.5** กด **ไม่มา** → ป้ายเปลี่ยนเป็น "ไม่มาตามนัด" สีแดง และปุ่มด่วนหายไปทั้งหมด (จบวงจรแล้ว)
- [ ] **4.6** กด **ยกเลิก** → ต้องมีกล่องถามเหตุผลก่อน กรอกแล้วยืนยัน → การ์ดเปลี่ยนเป็นสีเทาและแสดงเหตุผลใต้การ์ด
- [ ] **4.7** หน้า **ปฏิทินนัด** → กดสัปดาห์ก่อน/ถัดไป → คิวเปลี่ยนตามสัปดาห์ และวันนี้มีกรอบสีทอง
- [ ] **4.8** ในปฏิทิน กด **ย้ายเวลา** ของนัดหนึ่งใบ → เลือกเวลาใหม่ → นัดเดิมกลายเป็น "ยกเลิก" (เหตุผล: ย้ายไปเวลาใหม่) และมีใบใหม่ในเวลาที่เลือก
- [ ] **4.9** เปิดรายละเอียดลูกค้าคนนั้น → ประวัติต้องเห็นทั้งใบที่ถูกยกเลิกและใบใหม่ (ตอบได้ว่าเคยย้ายมาจากเวลาไหน)
- [ ] **4.10** ลองกด **มาแล้ว** กับนัดที่ยกเลิกไปแล้ว (ผ่าน Swagger `PATCH /api/appointments/:id/complete`) → ต้องถูกปฏิเสธ ไม่ใช่ปิดงานสำเร็จ
- [ ] **4.11** เปิดหน้าคิววันนี้ทิ้งไว้ แล้วเปลี่ยนสถานะนัดจากอีกแท็บ → แท็บแรกต้องเปลี่ยนตามเองภายใน 10 วินาที โดยไม่ต้องกดรีเฟรช

## 6. คิวว่าง (Waitlist) 📱

- [ ] **6.1** ที่แผง **คิวรอ** ข้างบอร์ด กด **เพิ่มชื่อ** → เลือกสมหญิง เลือกบริการ ระบุวันและช่วงเวลาที่ครอบคิวที่จะยกเลิก → บันทึก
- [ ] **6.2** ยกเลิกนัดที่อยู่ในช่วงเวลานั้นและเป็นบริการเดียวกัน
- [ ] **6.3** LINE เด้งการ์ด "มีคิวว่าง" พร้อมวันเวลาและปุ่มจอง (ภายในไม่กี่วินาที)
- [ ] **6.4** ในแผงคิวรอบนหน้าจอ สถานะของสมหญิงเปลี่ยนเป็น **เสนอคิวแล้ว** พร้อมบอกว่ากดรับได้ถึงกี่โมง
- [ ] **6.5** กดปุ่ม **จองคิวนี้** ใน LINE → บอตตอบยืนยัน และนัดใบใหม่โผล่บนบอร์ดคิวเองภายใน 10 วินาที
- [ ] **6.6** กดปุ่มเดิมซ้ำอีกครั้ง → ต้องได้ข้อความสุภาพว่าคิวนี้ถูกจองไปแล้ว ไม่ใช่จองซ้อนได้อีกใบ
- [ ] **6.7** **หมดเวลาข้อเสนอ**: เพิ่มคนเข้าคิวรออีกครั้ง ยกเลิกนัดอีกใบ แล้วอย่ากดรับ → กด **ข้าม 1 วัน** → ใบจองกลายเป็นหมดอายุ และแอดมินได้ข้อความบอกให้โทรตามเอง
- [ ] **6.8** กด **ถอนชื่อ** ในแผงคิวรอ → แถวหายไปจากรายการ
- [ ] **6.9** กด **กลับมาเวลาจริง**

> **ท่าเดโมสองเครื่อง**: ถ้ามีบัญชี LINE สองบัญชี ให้ผูกทั้งคู่แล้วใส่เข้าคิวรอทั้งสองคน ยกเลิกนัดหนึ่งใบ
> ทั้งสองเครื่องจะเด้งพร้อมกัน คนที่กดก่อนได้คิว อีกคนได้ข้อความว่ามีผู้จองแล้ว — ท่อนนี้ควรอัดวิดีโอเก็บไว้

## 7. ดึงลูกค้ากลับ (Win-back)

### 7.1 ตั้งค่าและดูผล

- [ ] **7.1.1** หน้า **ดึงลูกค้ากลับ** → การ์ดสี่ใบบนสุดแสดง ส่ง 12 · กลับมา 4 · 33.3% · 6,800 บาท · เฉลี่ย 1,700 บาทต่อคน
- [ ] **7.1.2** กด **สร้างแคมเปญ** → ใส่ชื่อ ข้อความที่มี `{name}` และจำนวนวัน → บันทึกได้
- [ ] **7.1.3** ใส่จำนวนวันน้อยกว่า 7 → ต้องถูกปฏิเสธพร้อมข้อความอธิบาย
- [ ] **7.1.4** กด **แก้ไข** แคมเปญ → ปิดสวิตช์ "เปิดใช้งาน" → ป้ายเปลี่ยนเป็น "ปิดอยู่" และปุ่ม **ยิงเดี๋ยวนี้** กดไม่ได้

### 7.2 ส่งจริง 📱

- [ ] **7.2.1** กด **ส่งทดสอบ** → LINE ของแอดมินได้ข้อความขึ้นต้นด้วย 🧪 พร้อมข้อความจริงที่แทนชื่อว่า "คุณลูกค้า"
- [ ] **7.2.2** สร้างแคมเปญใหม่ที่ตั้ง "หายไปเกิน" เป็น **7 วัน** (สมหญิงมาล่าสุด 7 วันที่แล้ว จะได้เข้าเกณฑ์)
- [ ] **7.2.3** กด **ยิงเดี๋ยวนี้** → ต้องมีกล่องถามยืนยันก่อน อ่านคำเตือนแล้วกดส่ง
- [ ] **7.2.4** ผลลัพธ์บอกจำนวน เข้าเกณฑ์ / ส่งสำเร็จ / ไม่สำเร็จ — สำเร็จ 1 คน (สมหญิง) ที่เหลือไม่สำเร็จเพราะเป็น `lineUserId` ปลอมของข้อมูลตัวอย่าง
- [ ] **7.2.5** LINE ได้ข้อความโปรที่ขึ้นต้นด้วยชื่อ "สมหญิง ใจดี" จริง
- [ ] **7.2.6** สังเกตว่าการส่งใช้เวลาประมาณ 1 วินาทีต่อคน (หน่วงไว้กัน rate limit ของ LINE)
- [ ] **7.2.7** กด **ยิงเดี๋ยวนี้** ซ้ำอีกครั้ง → จำนวน "เข้าเกณฑ์" ต้องลดลง 1 และ LINE **ต้องไม่ได้รับข้อความซ้ำ**
- [ ] **7.2.8** หน้า **ข้อความที่ส่ง** กรองชนิด "ดึงลูกค้ากลับ" → เห็นทั้งแถวสำเร็จและไม่สำเร็จครบตามจำนวน

### 7.3 ตัวเลข ROI เกิดเอง

- [ ] **7.3.1** กด **ดูผล** ของแคมเปญที่เพิ่งยิง → ตอนนี้ ส่ง 1 · กลับมา 0 · รายได้ 0
- [ ] **7.3.2** จองคิวให้สมหญิง (คนที่เพิ่งได้รับข้อความ) → กลับมาดูผล → **กลับมา 1 คน · 100%** โดยไม่ต้องกรอกอะไรเลย
- [ ] **7.3.3** กด **มาแล้ว** ที่นัดนั้น → กลับมาดูผลอีกครั้ง → **รายได้** ขึ้นเท่ากับราคาบริการที่ทำ
- [ ] **7.3.4** ไปหน้า **สรุปรายวัน** → การ์ด "ลูกค้าที่ดึงกลับมาได้ (เดือนนี้)" นับเพิ่มขึ้นตาม

## 8. คอร์ส

- [ ] **8.1** หน้า **คอร์ส** → กด **เพิ่มคอร์สที่ขาย** → ใส่ชื่อ จำนวนครั้ง อายุเป็นวัน ราคา → บันทึกได้ และโผล่ในรายการ "คอร์สที่ร้านขาย"
- [ ] **8.2** กด **บันทึกการซื้อคอร์ส** → เลือกลูกค้าและคอร์ส → ข้อความแจ้งผลบอกวันหมดอายุที่คำนวณให้แล้ว (วันที่ซื้อ + อายุคอร์ส)
- [ ] **8.3** รายการ "คอร์สที่ลูกค้าถืออยู่" แสดงแถบครั้งคงเหลือเต็มหลอด
- [ ] **8.4** **ตัดครั้ง**: จองคิวให้ลูกค้าคนนั้น ในฟอร์มจองจะมีช่อง "ตัดครั้งจากคอร์ส" ให้เลือก → เลือกแล้วจอง
- [ ] **8.5** กด **มาแล้ว** ที่นัดนั้น → กลับมาหน้าคอร์ส แถบครั้งคงเหลือลดลง 1 ครั้ง
- [ ] **8.6** การ์ดคิวของนัดนั้นมีป้าย "ตัดจากคอร์ส"
- [ ] **8.7** แก้อายุคอร์สในแม่แบบ (Swagger `PATCH /api/courses/packages/:id`) → วันหมดอายุของใบที่ขายไปแล้ว **ต้องไม่เปลี่ยน**
- [ ] **8.8** รายการ "ใกล้หมดอายุใน 30 วัน" ต้องมี 4 ราย และ **ต้องไม่มี** คนที่ใช้ครบทุกครั้งแล้ว (ข้อมูลตัวอย่างมีเคสนี้ไว้ 3 ใบ)
- [ ] **8.9** ระดับ VIEWER เปิดหน้าคอร์ส → คอลัมน์เบอร์โทรในรายการที่ควรโทรตามต้องเป็น "ไม่มีเบอร์"
- [ ] **8.10** 📱 **เตือนอัตโนมัติ**: สมหญิงมีคอร์สเหลือ 4 ครั้งและหมดอายุใน 9 วัน → กด **ข้าม 1 วัน** (งานนี้ตั้งไว้ 9 โมงเช้าทุกวัน) → LINE ได้ข้อความ 📋 บอกชื่อคอร์ส ครั้งที่เหลือ และวันหมดอายุ
- [ ] **8.11** กด **ข้าม 1 วัน** ซ้ำ → **ต้องไม่ได้รับซ้ำ** (กันสแปมด้วยการเว้น 30 วันต่อคน)
- [ ] **8.12** หน้า **ข้อความที่ส่ง** กรองชนิด "คอร์สใกล้หมดอายุ" → เห็นแถวที่เพิ่งส่ง
- [ ] **8.13** กด **กลับมาเวลาจริง**
