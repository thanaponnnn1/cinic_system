# แผน Phase 11: เว็บไซต์สาธารณะของคลินิก (ทำ SEO ได้)

**เว็บที่ Google อ่านได้ มีรูปเยอะ รีวิวเยอะ และพาคนไปจองคิวในหน้าที่ทำไว้แล้ว** · ต่อจาก [plan-customer-liff.md](plan-customer-liff.md) · ต.ค. 2569

> **เอกสารนี้คืออะไร**: แผนสร้างแอป Next.js ตัวที่สาม `site/` ใน monorepo เดิม เป็นหน้าร้านออนไลน์ของคลินิกที่ติดอันดับ Google ได้
> หน้าจองคิว `/c/*` (Phase 10) ยังเป็นแอปเดิม ทำหน้าที่ปลายทางของปุ่ม "จองคิว" ทุกปุ่มในเว็บนี้
> ตัดสินใจแล้ว (24 ต.ค. 2569): **แนวทาง ก.** แยกเป็นแอปใหม่ และ **เนื้อหาเก็บเป็นไฟล์ในโปรเจกต์** นักพัฒนาเป็นคนแก้ให้ในเวอร์ชันแรก
>
> **ขอบเขตรอบนี้ (24 ต.ค. 2569): เดโมสำหรับอัดคลิปเท่านั้น** ไม่มีรูปจริงของร้าน ใช้รูปเดโมชุดเดิมขยาย 2 เท่าด้วย lanczos พร้อมเพิ่มความคม (ไม่ใช่ AI ขยายแล้วไม่ได้เพิ่มรายละเอียด จึงจัดเลย์เอาต์ไม่ให้รูปไหนแสดงใหญ่เกินความละเอียดจริง และใส่ฟิล์มเกรนบางเบาทับรูปใหญ่) · ข้อมูลร้านเป็นข้อมูลสมมติและมีป้ายบอกที่ส่วนท้ายเว็บ · `SITE_MODE=demo` ตั้ง `noindex` ทั้งเว็บ กัน Google เก็บข้อมูลร้านสมมติ · ทำ S0 ถึง S5 ส่วน S6 (Vercel, Search Console) ไว้ทีหลัง · §9 ส่วนเว็บจริงและ §12 ใช้เมื่อขายให้คลินิกจริง

## 1. ทำไมต้องแยกเว็บใหม่

ตรวจหน้า `/c` ที่มีอยู่ด้วยการดึง HTML แบบที่ Google เห็น (24 ต.ค. 2569):

| สิ่งที่ Google ต้องเห็น | หน้า `/c` ตอนนี้ |
| --- | --- |
| ชื่อบริการ ชื่อช่าง ในเนื้อ HTML | ไม่มีเลย (โหลดจาก backend หลังเปิดหน้า) |
| หัวข้อ `<h1>` | ไม่มี |
| ข้อมูลโครงสร้าง JSON-LD | ไม่มี |
| `sitemap.xml`, `robots.txt`, canonical | ไม่มี |

หน้า `/c` ออกแบบมาเป็นแอปจองใน LINE จึงถูกต้องแล้วที่เป็นแบบนี้ ส่วนเว็บสาธารณะมีโจทย์ตรงข้าม คือต้องมีเนื้อหาครบตั้งแต่ HTML แรก และต้องเปิดได้แม้ backend ในเครื่องนักพัฒนาปิดอยู่

| ภาษา | ไทยอย่างเดียว `lang="th"` | ลูกค้าคลินิกในพื้นที่ค้นเป็นภาษาไทย |

## 3. หน้าในเว็บ

| หน้า | path | เป้าหมาย SEO | เนื้อหาหลัก |
| --- | --- | --- | --- |

| บริการแต่ละตัว | `/services/[slug]` | คำค้นต่อบริการ เช่น "ทรีตเมนต์หน้า <จังหวัด>" | รูป 4 ถึง 8 รูป, ราคา, ระยะเวลา, ขั้นตอน, เหมาะกับใคร, ดูแลหลังทำ, คำถามที่พบบ่อย, รีวิวของบริการนี้, ปุ่มจองที่เลือกบริการไว้แล้ว |

| ทีมช่าง | `/team` และ `/team/[slug]` | ชื่อช่าง (คนค้นชื่อช่างที่ชอบ) | รูป, ประสบการณ์, บริการที่ถนัด, ปุ่ม "จองกับช่างคนนี้" |
| แกลเลอรี | `/gallery` | "บรรยากาศร้าน" และรูปติด Google Images | รูปจำนวนมาก แบ่งหมวด เปิดดูเต็มจอได้ |
| รีวิว | `/reviews` | ความน่าเชื่อถือ | คะแนนเฉลี่ย, กำแพงรีวิวทั้งหมด, กรองตามบริการ |

| นโยบายความเป็นส่วนตัว | `/privacy` | ไม่ใช่เป้า SEO | จำเป็นตาม PDPA ช่องติ๊กยินยอมในหน้าจองต้องลิงก์มาที่นี่ |

## 5. โครงสร้างโค้ด

```
site/
  content/                 เนื้อหาทั้งหมด แก้ที่นี่ที่เดียว
    site.ts                ชื่อร้าน ที่อยู่ เบอร์ เวลาเปิดปิด เลขที่ใบอนุญาต ลิงก์ LINE ประเภทธุรกิจ
    services.ts            บริการ: slug, ชื่อ, หมวด, ราคา, ระยะเวลา, รูป, ขั้นตอน, FAQ
    courses.ts             คอร์สและราคา
    team.ts                ช่าง: slug, ชื่อ, ตำแหน่ง, ประวัติ, รูป, บริการที่ถนัด
    reviews.ts             รีวิว: ข้อความ, คะแนน, บริการ, วันที่, แหล่งที่มา, ยินยอมแล้ว, isSample
    gallery.ts             รูป: ไฟล์, alt, หมวด, ขนาด
    articles/*.mdx         บทความ
  src/
    content/schema.ts      zod schema ของทุกไฟล์ใน content/ + กฎ SEO (§7)
    content/load.ts        โหลดและตรวจครั้งเดียวตอน build ส่วนอื่นได้ชนิดข้อมูลที่ตรวจแล้ว
    seo/                   metadata ต่อหน้า, JSON-LD builder, sitemap, robots
    effects/               เอฟเฟกต์ทีละไฟล์ แต่ละตัวมีโหมดไม่เคลื่อนไหว
    sections/              ส่วนของหน้า (hero, bento, reviews, ...) ประกอบจาก effects
    app/                   เส้นทางตาม §3
  public/images/           รูปต้นฉบับความละเอียดสูง (next/image ย่อให้เอง)
```

รูปร่างข้อมูลหลัก (ตัดย่อ):

```ts
type Review = {
  id: string;
  text: string;
  rating: 1 | 2 | 3 | 4 | 5;
  serviceSlug?: string;
  authorDisplay: string; // ชื่อย่อที่ลูกค้ายินยอมให้แสดง เช่น "คุณ ม."
  date: string; // ISO
  source: 'line-after-visit' | 'in-store' | 'sample';
  consent: boolean; // ยินยอมให้แสดงบนเว็บ
  isSample: boolean; // true = รีวิวตัวอย่างของเดโม ห้ามออก JSON-LD และต้องมีป้าย
};
```

การเชื่อมกับหน้าจอง: บริการในเว็บอ้างด้วย `slug` ส่วน backend ตอนนี้ใช้ id แบบ cuid ซึ่งเปลี่ยนทุกครั้งที่สร้างฐานข้อมูลใหม่ จึงต้องเพิ่ม `Service.slug` (unique) ใน backend ให้ seed ตั้งค่าให้ตรงกับ `site/content/services.ts` และให้หน้า `/c/book` รับ `?service=` ได้ทั้ง slug และ id มีสคริปต์ตรวจตอน build ว่า slug ในเว็บมีอยู่จริงใน `GET /api/customer/shop` (ถ้าเข้า backend ไม่ได้ให้เตือน ไม่ทำให้ build ล้ม)

## 6. SEO ที่ต้องมีครบ

- **metadata ต่อหน้า**: title ไม่เกิน 60 ตัวอักษร, description 70 ถึง 160 ตัวอักษร, canonical, Open Graph, ภาพแชร์ต่อบริการสร้างด้วย `opengraph-image.tsx`
- **`sitemap.ts` และ `robots.ts`**: สร้างจากเนื้อหาอัตโนมัติ หน้า `/privacy` และ 404 ไม่อยู่ใน sitemap
- **JSON-LD**:
  - ทุกหน้า: ธุรกิจตาม `site.ts` (`BeautySalon` หรือ `MedicalClinic` เลือกได้ตามใบอนุญาตจริงของร้าน) พร้อมที่อยู่ เวลาเปิดปิด เบอร์ พิกัด
  - หน้าบริการ: `Service` + `Offer` ราคาเป็นบาท, `FAQPage`, `BreadcrumbList`
  - บทความ: `Article`
  - รีวิว: ใส่ `Review` และ `AggregateRating` เฉพาะรีวิวที่ `isSample=false` และ `consent=true` เท่านั้น
- **ข้อเท็จจริงที่ต้องบอกเจ้าของร้าน**: Google ไม่แสดงดาวรีวิวในผลค้นหาสำหรับรีวิวที่ธุรกิจเก็บและแสดงบนเว็บตัวเอง (นโยบาย self-serving reviews) ดาวที่คนเห็นใน Google มาจาก Google Business Profile รีวิวบนเว็บเราจึงช่วยเรื่องความน่าเชื่อถือและการตัดสินใจจอง ไม่ใช่ดาวในผลค้นหา ต้องทำ Google Business Profile คู่กันเสมอ
- **Local SEO**: ชื่อ ที่อยู่ เบอร์ ต้องตรงกับ Google Business Profile ทุกตัวอักษร · แผนที่ฝังแบบกดแล้วค่อยโหลด
- **รูป**: alt text ภาษาไทยที่บอกว่าในรูปคืออะไรทุกรูป, ชื่อไฟล์ภาษาอังกฤษสื่อความหมาย, `next/image` พร้อม `sizes`, รูป hero ตั้ง `priority`
- **Core Web Vitals บนมือถือ**: LCP ไม่เกิน 2.5 วินาที, CLS ต่ำกว่า 0.1, INP ต่ำกว่า 200ms · JavaScript ตอนโหลดหน้าแรกไม่เกิน 150KB (gzip) · เอฟเฟกต์หนักโหลดแบบ dynamic import เมื่อเลื่อนถึงเท่านั้น
- **หน้าจอง `/c/*` ใส่ `noindex`**: ไม่ให้หน้าแอปไปแย่งอันดับกับหน้าบริการ

## 7. กฎที่บังคับด้วยโค้ด (build ล้มถ้าผิด)

เนื้อหาจะถูกแก้บ่อยและคนแก้ไม่ใช่ผู้เชี่ยวชาญ SEO ทุกครั้ง กฎพวกนี้จึงอยู่ใน `src/content/schema.ts` ไม่ได้อยู่ในเอกสาร:

- ทุกรูปต้องมี alt ยาว 8 ถึง 125 ตัวอักษร และห้ามซ้ำกัน
- รูป hero และรูปหลักของบริการต้องกว้างอย่างน้อย 1600px
- title และ description ต้องอยู่ในช่วงความยาวตาม §6
- slug ห้ามซ้ำ และใช้ได้แค่ a-z 0-9 และขีด
- รีวิวที่ `consent=false` ห้ามแสดง · รีวิว `isSample=true` ต้องไม่ออก JSON-LD และหน้าเว็บต้องแสดงป้าย "ตัวอย่าง"
- ถ้า `NODE_ENV=production` และ `SITE_MODE=live` แต่ยังมีรีวิวตัวอย่างหรือรูปเดโมอยู่ build ล้ม (กันส่งมอบเว็บจริงพร้อมของปลอม)
- บริการทุกตัวต้องมี FAQ อย่างน้อย 3 ข้อ และรูปอย่างน้อย 4 รูป

## 8. รีวิวเยอะ ๆ ให้ได้มาจริง

**เวอร์ชันแรก (เดโม)**: รีวิวตัวอย่าง 24 ถึง 30 ชิ้นใน `reviews.ts` ตั้ง `isSample: true` ทุกชิ้น มีป้าย "ตัวอย่าง" และไม่ออก JSON-LD

**เว็บจริงของคลินิก**: ห้ามใช้รีวิวแต่งเด็ดขาด และไม่คัดลอกรีวิวจาก Google Maps มาแปะ (ผิดเงื่อนไขของ Google) ทางที่ถูกคือ:

1. ใส่รีวิวที่ร้านมีหลักฐานและได้ความยินยอมแล้วลง `reviews.ts`
2. ปุ่ม "ดูรีวิวทั้งหมดบน Google" ลิงก์ไป Google Business Profile ของร้าน
3. เฟสสอง (§11): ระบบขอรีวิวอัตโนมัติหลังรับบริการผ่าน LINE ซึ่งเป็นจุดขายได้เอง

## 9. รูปเยอะ ๆ

**เวอร์ชันแรก (เดโม)**: ใช้ 19 รูปใน `frontend/public/demo/` และหาเพิ่มให้ครบอย่างน้อย 40 รูป ทุกรูปตั้ง `isDemo: true` ในข้อมูล
ข้อจำกัด: รูปเดิมกว้างแค่ 736px ต่ำกว่ากฎ 1600px ใน §7 จึงต้องผ่อนกฎนี้เฉพาะ `SITE_MODE=demo` และรูปเดโมห้ามขึ้นเว็บจริง

**เว็บจริง**: ต้องเป็นรูปของร้านจริงทั้งหมด (รูป AI หรือรูปจากเว็บอื่นทำให้ลูกค้าเข้าใจผิดเรื่องสถานที่ และอาจติดลิขสิทธิ์) ขอจากร้านตามรายการนี้ กว้างอย่างน้อย 1600px:

| หมวด | จำนวน |
| --- | --- |
| หน้าร้านภายนอก ป้ายร้าน | 3 |
| ล็อบบี้ เคาน์เตอร์ มุมรอ | 5 |
| ห้องทำทรีตเมนต์ เตียง อุปกรณ์ | 6 |
| แต่ละบริการ ขณะทำจริง (ได้รับอนุญาตจากลูกค้าในภาพ) | บริการละ 4 |
| ทีมช่าง ยูนิฟอร์มเดียวกัน หน้าตรง และขณะทำงาน | คนละ 2 |
| ผลิตภัณฑ์ที่ใช้ | 4 |

**รูปก่อนและหลังทำ**: ต้องได้ความยินยอมเป็นลายลักษณ์อักษรจากผู้รับบริการ และการโฆษณาสถานพยาบาลมีกฎควบคุม ให้เจ้าของคลินิกยืนยันกับข้อกำหนดที่ร้านต้องปฏิบัติก่อน เวอร์ชันแรกไม่ทำส่วนนี้

## 11. เฟสสอง (ขายต่อได้)

1. **ระบบขอรีวิวหลังรับบริการ**: พนักงานกด "รับบริการแล้ว" → ระบบส่ง LINE ขอรีวิว → ลูกค้าให้คะแนนในหน้า `/c` พร้อมติ๊กยินยอมแสดงชื่อย่อ → เข้าคิวให้เจ้าของร้านอนุมัติ → เว็บ rebuild แล้วแสดง จำนวนรีวิวที่เพิ่มขึ้นต่อเดือนคือตัวเลขที่ขายได้
2. **เจ้าของร้านแก้เนื้อหาเอง**: ย้ายเนื้อหาจากไฟล์เข้าฐานข้อมูล ทำหน้าแก้ในหน้าพนักงาน แล้วสั่ง rebuild ผ่าน Vercel Deploy Hook ใช้ schema เดิมจาก §7 ตรวจเหมือนเดิม

## 12. สิ่งที่ต้องขอจากคลินิกก่อนทำเว็บจริง

- ชื่อร้านตามที่จดทะเบียน ที่อยู่ เบอร์ พิกัด เวลาเปิดปิด (ตรงกับ Google Business Profile)
- เลขที่ใบอนุญาตสถานพยาบาล (ถ้าเป็นคลินิก) และประเภทธุรกิจที่ถูกต้อง
- รายการบริการ ราคา ระยะเวลา และคำอธิบายที่ร้านยืนยันว่าพูดได้
- ประวัติช่างและการยินยอมให้ใช้รูป
- รูปตามรายการใน §9
- รีวิวจริงที่มีหลักฐานและความยินยอม
- หัวข้อบทความ 3 ถึง 5 เรื่องที่ลูกค้าถามบ่อย
