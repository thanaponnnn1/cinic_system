# 8 กลุ่มลูกค้าที่ระบบนี้ขายได้ — ขยายขอบเขตงานและวิธีตั้งราคา

เอกสารอ้างอิงตอนคุยกับลูกค้า · PriceRadar / ระบบดึงข้อมูลอัตโนมัติ · thanapon.ji

> **ใช้ยังไง** — เปิดไฟล์นี้ตอนลูกค้าทักมา อ่านหัวข้อที่ตรงกับธุรกิจเขา ใช้ช่อง "ถามก่อนเสนอราคา" คัดกรองว่างานทำได้จริงไหม แล้วค่อยเสนอราคาตามช่วงที่แนะนำ
>
> อ่านหัวข้อ **"ลูกค้าหนึ่งราย = งานหลายชิ้น"** ก่อนเสมอ เพราะหัวข้อ 1–8 เขียนไว้เป็นหนึ่งธุรกิจหนึ่งปัญหาเพื่อให้อ่านง่าย ซึ่งไม่ตรงกับความจริง

## เครื่องยนต์เดียวกันทั้ง 8 งาน

ทุกงานในเอกสารนี้คือรูปแบบเดียวกัน ต่างกันแค่ "ดึงจากไหน" กับ "เกณฑ์เท่าไหร่" ซึ่งเป็นข้อมูลในฐานข้อมูล ไม่ใช่โค้ด

```
ดึงข้อมูลตามเวลา → เก็บประวัติ → เทียบเกณฑ์ → เตือนคนที่ต้องรู้ → ดูย้อนหลังได้
```

**สิ่งที่ทุกงานได้เหมือนกัน** — ทำงานอัตโนมัติบนเซิร์ฟเวอร์ · เก็บประวัติย้อนหลัง · Dashboard + กราฟ · แจ้งเตือนเข้า LINE · REST API ให้ระบบอื่นดึงต่อ · **แจ้งเตือนเมื่อระบบตัวเองพัง**

> ราคาอ้างอิงจากแพ็กในหน้างาน: `เชื่อม 1 จุด 3,900` · `ระบบอัตโนมัติ 9,900` · `API ครบชุด 19,900` งานที่เกินจากนี้ให้เสนอราคาเฉพาะงาน

## ลูกค้าหนึ่งราย = งานหลายชิ้น (อ่านก่อนเสนอราคา)

หัวข้อ 1–8 ข้างล่างเขียนไว้เป็น "หนึ่งธุรกิจ หนึ่งปัญหา" เพื่อให้อ่านง่าย **แต่ความจริงไม่ใช่แบบนั้น** ธุรกิจหนึ่งรายมีปัญหาซ้อนกันอยู่ 4–7 อย่างเสมอ และนี่คือจุดที่ทำเงินได้มากที่สุด

**ปัญหาของลูกค้ารายเดียวกัน เรียงตามลำดับที่ควรขาย**

| ธุรกิจ                  | ขายก่อน (เจ็บสุด)              | ขายต่อรอบ 2–3                          | ขายทีหลัง                                                |
| ----------------------- | ------------------------------ | -------------------------------------- | -------------------------------------------------------- |
| **คาเฟ่ / ร้านอาหาร**   | ยอดขายรายชั่วโมง + สรุปปิดร้าน | วัตถุดิบ/ของเสีย · ตารางเวร-ค่าแรง     | เดลิเวอรี่หลายเจ้า (GP ไม่เท่ากัน) · ลูกค้าประจำ · รีวิว |
| **หอพัก / อพาร์ตเมนต์** | มิเตอร์น้ำ-ไฟ + ออกบิล         | ทวงค่าเช่าค้าง · สัญญาใกล้หมด          | แจ้งซ่อม · เงินประกัน/เข้า-ออก · บัญชีรายรับ             |
| **โรงแรม / ที่พัก**     | จองใหม่เด้ง + สรุปยอด          | สถานะห้อง/แม่บ้าน · ราคาตามฤดูกาล      | รีวิว · ลูกค้าเก่ากลับมาพัก · สต็อกของใช้                |
| **คลินิก / เสริมสวย**   | เตือนนัด ลด no-show            | ดึงลูกค้าที่หายกลับ · คอร์สใกล้หมดอายุ | ค่าคอมช่าง/หมอ · สต็อกเวชภัณฑ์ · ใบเสร็จ-ภาษี            |
| **บริษัททั่วไป (lead)** | ฟอร์ม → เซลส์ + เตือนถ้าเงียบ  | ติดตามสถานะจนปิดการขาย                 | ใบเสนอราคา · ลูกหนี้ · ต่อสัญญาลูกค้าเก่า                |
| **ร้านค้าออนไลน์**      | เตือนสต็อกต่ำ                  | ของไม่ขยับ/เงินจม · รายงานให้บัญชี     | ต้นทุน-กำไรจริงต่อ SKU · คืนสินค้า                       |
| **ขายหลายช่องทาง**      | รวมออเดอร์หน้าเดียว            | ซิงค์สต็อกกันขายเกิน                   | ส่งเข้าบัญชี · กำไรจริงต่อช่องทาง · แชท/รีวิว            |

### ทำไมเรื่องนี้สำคัญกว่าที่คิด

**เลขจริง** — ขายงานเดียวจบได้ 9,900 บาท แต่ถ้าลูกค้าคนเดิมจ้างต่ออีก 3 รอบใน 18 เดือน คุณได้ **35,000–45,000 บาทจากลูกค้าคนเดียว** โดยไม่ต้องหาลูกค้าใหม่เลย

และงานรอบที่ 2 **ต้นทุนคุณถูกกว่ารอบแรกมาก** เพราะใช้ฐานข้อมูลเดิม ระบบล็อกอินเดิม LINE เดิม เซิร์ฟเวอร์เดิม — เหลือแค่เขียนส่วนที่เพิ่ม กำไรต่อชั่วโมงจึงสูงกว่า

**ลูกค้าเก่าปิดง่ายกว่าลูกค้าใหม่หลายเท่า** เพราะเขาเห็นแล้วว่าคุณส่งมอบจริง ไม่ต้องพิสูจน์ตัวเองใหม่ ไม่ต้องแข่งราคากับใคร

### วิธีเสนอราคาให้ถูกวิธี

**อย่าเสนอทีเดียว 60,000** — SME เห็นเลขนี้แล้วเงียบหาย ให้ทำแบบนี้แทน

1. **ถามให้ครบว่าเขาเจ็บอะไรบ้าง** — จดไว้ทุกข้อ แม้ยังไม่ขายรอบนี้
2. **เสนอเฉพาะข้อที่เจ็บที่สุดข้อเดียว** ราคา 9,900 ทำเสร็จใน 2 สัปดาห์
3. **บอกให้เขารู้ว่าที่เหลือทำต่อได้** — "ระบบนี้ต่อยอดไปทำเรื่องวัตถุดิบกับตารางเวรได้ ไว้เรื่องนี้นิ่งแล้วค่อยคุยกัน"
4. **หลังส่งมอบ 1–2 เดือน กลับไปถามว่าเป็นยังไงบ้าง** — นี่คือจังหวะขายรอบ 2 ที่ดีที่สุด

ประโยคข้อ 3 สำคัญมาก มันทำให้ลูกค้ารู้ว่ายังมีอะไรให้ทำต่อ **โดยที่ไม่รู้สึกว่ากำลังโดนขายของ**

> ⚠️ **แต่ต้องแยกสัญญาให้ขาด** — "ต่อยอดได้" ไม่ได้แปลว่า "แถมให้ในราคาเดิม" ถ้าลูกค้าขอเพิ่มระหว่างงานรอบแรก ให้ตอบว่า "ได้ครับ อันนั้นเป็นเฟสถัดไป เดี๋ยวผมทำใบเสนอราคาแยกให้" ทุกครั้ง ไม่งั้นงาน 9,900 จะกลายเป็นงาน 40,000 ที่ได้เงิน 9,900

## 1. ร้านค้าออนไลน์ — ระบบเฝ้าสต็อก

**ปัญหาจริง:** ของหมดแล้วเพิ่งรู้ตอนลูกค้าสั่ง · สั่งของเข้ามากไปจนเงินจม · ไม่รู้ว่าตัวไหนขายดีจนต้องรีบเติม

**ทำได้มากกว่าแค่เตือนของใกล้หมด**

- ตั้งจุดสั่งซื้อแยกรายสินค้า ไม่ใช่ตัวเลขเดียวใช้ทั้งร้าน
- **คำนวณจุดสั่งซื้อจากยอดขายเฉลี่ย** แทนที่จะให้เจ้าของเดาเอง
- บอกว่า "ของชิ้นนี้จะหมดในอีก 6 วัน" จากอัตราการขายจริง
- เตือนสินค้าที่ไม่ขยับเลยเกิน 60 วัน — เงินจมที่เจ้าของมักลืม
- เตือนสินค้าที่ขายดีผิดปกติ จะได้สั่งเพิ่มทันก่อนของขาด
- รายงานสต็อกทุกเช้าเข้า LINE
- ประวัติการเคลื่อนไหวย้อนหลัง ใช้ตอบคำถามว่าของหายไปไหน
- Export ให้ฝ่ายบัญชีทุกสิ้นเดือน

**ดึงข้อมูลจากไหน:** Google Sheet ที่ร้านใช้อยู่ (ง่ายสุด) · ระบบ POS ที่มี API · Shopee/Lazada Open Platform (ลูกค้าเป็นคนกดอนุญาต)

**ราคาที่ควรเสนอ:** 9,900 – 19,900

**ถามก่อนเสนอราคา**

- ตอนนี้เก็บข้อมูลสต็อกไว้ที่ไหน (Excel / Sheet / โปรแกรมอะไร)
- ถ้าเป็นโปรแกรม มี API หรือ export อัตโนมัติได้ไหม
- มีกี่ SKU และอัปเดตสต็อกบ่อยแค่ไหน
- ใครเป็นคนรับการแจ้งเตือน

## 2. ขายหลายช่องทาง — รวมออเดอร์ที่เดียว

**ปัญหาจริง:** เปิด 4 แอปทุกเช้า · คีย์ออเดอร์ซ้ำเข้าระบบบัญชี · สต็อกตีกันจนขายเกินแล้วต้องยกเลิกออเดอร์

**ทำได้มากกว่าแค่รวมออเดอร์**

- ดึงออเดอร์จากทุกช่องทางมาไว้หน้าเดียว เห็นสถานะครบ
- แจ้งเตือนออเดอร์ใหม่ทันทีเข้า LINE
- **เตือนออเดอร์ที่ยังไม่แพ็คเกิน X ชั่วโมง** — ป้องกันคะแนนร้านตก
- สรุปยอดรายวัน/สัปดาห์/เดือน แยกตามช่องทาง
- **หักค่า GP แต่ละแพลตฟอร์มให้ เห็นว่าช่องทางไหนกำไรจริงมากกว่า** — ข้อนี้ลูกค้าประหลาดใจเสมอ
- **ซิงค์สต็อกกลับทุกช่องทาง กันขายเกิน** ← มูลค่าสูงสุดของงานกลุ่มนี้
- ส่งข้อมูลเข้าระบบบัญชี ไม่ต้องคีย์ซ้ำ

**ดึงข้อมูลจากไหน:** Shopee / Lazada / TikTok Shop **Open Platform API** ที่ลูกค้าเป็นคนกดอนุญาตให้เข้าถึงข้อมูลร้านตัวเอง

**ราคาที่ควรเสนอ:** 19,900 ขึ้นไป (งานใหญ่สุดในเอกสารนี้)

> ⚠️ **ต้องเช็คก่อนรับงานเสมอ** — การเชื่อม Open Platform ต้องสมัคร Developer Account และรออนุมัติ ซึ่งใช้เวลาและอยู่นอกการควบคุมเรา **อย่าตกลงวันส่งมอบก่อนที่บัญชีจะได้รับอนุมัติ** และเขียนเงื่อนไขข้อนี้ในใบเสนอราคา

**ถามก่อนเสนอราคา**

- ขายอยู่กี่ช่องทาง ช่องทางไหนบ้าง
- เคยสมัคร Developer Account ของแพลตฟอร์มไหนไว้แล้วหรือยัง
- ต้องการแค่ "ดูรวม" หรือต้องการ "ซิงค์สต็อกกลับ" ด้วย (ราคาต่างกันมาก)
- มีระบบบัญชีอะไรที่ต้องส่งข้อมูลเข้า

## 3. ร้านอาหาร — ระบบวัตถุดิบ

**ปัญหาจริง:** วัตถุดิบหมดกลางวันขายดี · ของเสียทิ้งทุกสัปดาห์ · ต้นทุนขึ้นแต่ไม่รู้ว่าขึ้นเท่าไหร่ · สงสัยว่าของหายแต่พิสูจน์ไม่ได้

**ทำได้มากกว่าแค่เตือนของใกล้หมด**

- เตือนวัตถุดิบใกล้หมด แยกตามความถี่ที่ใช้จริง
- **เตือนของใกล้หมดอายุ เรียงตามวันที่รับเข้า (FIFO)** ลดของเสีย
- ตัดสต็อกอัตโนมัติตามเมนูที่ขายไป (ผูกสูตรอาหารกับวัตถุดิบ)
- **คำนวณต้นทุนต่อจาน และเตือนเมื่อวัตถุดิบขึ้นราคาจนกำไรหด**
- **เตือนเมื่อยอดใช้วัตถุดิบไม่สมเหตุสมผลกับยอดขาย** ← ข้อนี้เจ้าของร้านจ่ายเพื่อมันโดยเฉพาะ
- รายงานของเสีย/ของทิ้งรายสัปดาห์
- สร้างใบสั่งซื้อซัพพลายเออร์อัตโนมัติเมื่อถึงจุดสั่งซื้อ

**ดึงข้อมูลจากไหน:** Google Sheet ที่ร้านใช้อยู่ · ระบบ POS ที่มี API · ฟอร์มบันทึกรับเข้า-เบิกออกที่เราทำให้

**ราคาที่ควรเสนอ:** 9,900 – 19,900

**ถามก่อนเสนอราคา**

- มีสูตรอาหารเป็นลายลักษณ์อักษรไหม (ถ้าไม่มี งานจะบานปลาย)
- ใช้ POS อะไร ดึงข้อมูลออกได้ไหม
- มีกี่เมนู กี่วัตถุดิบ
- มีกี่สาขา

## 4. คาเฟ่ / ร้านอาหาร — ระบบวิเคราะห์ยอดขาย

**ปัญหาจริง:** รู้แค่ยอดรวมสิ้นวัน · ไม่รู้ว่าช่วงไหนควรเพิ่มหรือลดคน · ยอดตกแล้วเพิ่งรู้ตอนสิ้นเดือน

**ทำได้มากกว่าแค่กราฟยอดขาย**

- กราฟยอดขายรายชั่วโมง เทียบกับวันเดียวกันของสัปดาห์ก่อน
- **เตือนเมื่อยอดต่ำผิดปกติระหว่างวัน** — บางครั้งไม่ใช่ร้านเงียบ แต่เครื่อง POS พังหรือพนักงานไม่คีย์
- เมนูขายดี / เมนูที่ไม่มีใครสั่งเลย (ควรตัดออกจากเมนู)
- ยอดเฉลี่ยต่อบิล และแนวโน้มว่าขึ้นหรือลง
- **บอกว่าชั่วโมงไหนควรเพิ่ม-ลดพนักงาน** ← ประหยัดค่าแรงเป็นเงินจริงทุกเดือน
- เทียบระหว่างสาขา (ถ้ามีหลายสาขา)
- สรุปปิดร้านทุกคืนเข้า LINE เจ้าของ ไม่ต้องโทรถามผู้จัดการ

**ดึงข้อมูลจากไหน:** POS ที่มี API · ไฟล์ export รายวันจาก POS · Google Sheet

**ราคาที่ควรเสนอ:** 9,900 – 19,900

**ถามก่อนเสนอราคา**

- ใช้ POS ยี่ห้ออะไร export ข้อมูลรายบิลได้ไหม
- ต้องการดูละเอียดระดับรายเมนู หรือแค่ยอดรวมพอ
- มีกี่สาขา ต้องเทียบกันไหม

## 11. หอพัก / อพาร์ตเมนต์

**ปัญหาจริง:** ไล่ทวงค่าเช่าเองทุกเดือน · จดมิเตอร์แล้วมานั่งคิดบิลด้วยเครื่องคิดเลข · ลืมว่าสัญญาห้องไหนใกล้หมด

**ทำได้มากกว่าแค่เตือนค่าเช่าค้าง**

- เตือนค่าเช่าค้างชำระ แยกกลุ่มตามจำนวนวันที่ค้าง
- **ส่งใบแจ้งหนี้อัตโนมัติทุกเดือนเข้า LINE ผู้เช่าทีเดียวทุกห้อง**
- เตือนผู้เช่าล่วงหน้าก่อนครบกำหนดชำระ ลดการค้างตั้งแต่ต้น
- **บันทึกเลขมิเตอร์น้ำ-ไฟ แล้วคำนวณบิลให้อัตโนมัติ** ← งานที่เจ้าของหอเกลียดที่สุด
- เตือนสัญญาใกล้หมดอายุล่วงหน้า 30/60 วัน
- ห้องว่างเกิน X วัน → เตือนให้ลงประกาศ
- ประวัติการชำระรายห้อง ใช้ตัดสินใจตอนต่อสัญญา
- รายงานรายได้และอัตราการเข้าพักรายเดือน

**ดึงข้อมูลจากไหน:** Excel/Sheet ที่เจ้าของใช้อยู่ (เกือบทุกรายเป็นแบบนี้) · ฟอร์มจดมิเตอร์ที่เราทำให้ใช้บนมือถือ

**ราคาที่ควรเสนอ:** 9,900 – 19,900

> 🔒 มีข้อมูลส่วนบุคคลของผู้เช่า (ชื่อ เบอร์ เลขบัตร) — ต้องคุยเรื่อง PDPA กับลูกค้า เก็บเท่าที่จำเป็น และแบ่งสิทธิ์ว่าใครเห็นอะไรได้

**ถามก่อนเสนอราคา**

- กี่ห้อง กี่อาคาร
- ตอนนี้จดมิเตอร์และคิดบิลยังไง
- ผู้เช่าส่วนใหญ่ใช้ LINE ไหม
- ต้องการให้ผู้เช่าดูบิลตัวเองได้ด้วยหรือแค่เจ้าของดู

## 12. โรงแรม / ที่พัก

**ปัญหาจริง:** ต้องเปิดหลาย OTA ดูว่ามีจองเข้ามาไหม · ไม่รู้ว่าปีนี้ยอดดีกว่าปีก่อนหรือแย่กว่า · ห้องว่างช่วงวันหยุดยาวแต่รู้ตัวช้าเกินจัดโปร

**ทำได้มากกว่าแค่แจ้งเตือนการจอง**

- จองใหม่เด้งเข้า LINE ทันที พร้อมรายละเอียดห้องและวันเข้าพัก
- **ยอดจองเทียบช่วงเดียวกันของปีก่อน** ใช้ตัดสินใจเรื่องราคา
- อัตราการเข้าพักรายวัน/รายเดือน เป็นกราฟ
- **เตือนเมื่อห้องยังว่างเยอะในช่วงวันหยุดยาวที่ใกล้เข้ามา** จะได้จัดโปรทัน
- รายการ check-in / check-out ของวันนี้ ส่งให้แม่บ้านทุกเช้า
- รายได้เฉลี่ยต่อห้องที่มี (RevPAR) — ตัวเลขที่คนทำโรงแรมดูจริง
- เตือนเมื่อมีรีวิวใหม่ (ถ้าช่องทางนั้นเปิดให้ดึง)

**ดึงข้อมูลจากไหน:** ระบบ PMS ของโรงแรม · Google Calendar (ที่พักเล็กหลายแห่งใช้) · Sheet · OTA API เฉพาะที่เป็น partner

**ราคาที่ควรเสนอ:** 9,900 – 19,900

> ⚠️ Agoda/Booking ต้องเป็น partner ถึงจะมี API — **ถามก่อนรับงานเสมอ** ถ้าไม่มี ให้เสนอทำจาก PMS หรือ Calendar แทน

**ถามก่อนเสนอราคา**

- กี่ห้อง
- รับจองผ่านช่องทางไหนบ้าง
- ใช้ระบบ PMS อะไร หรือจดใน Excel/Calendar
- มีสิทธิ์เข้าถึง API ของ OTA ไหม

## 13. คลินิก / ร้านเสริมสวย

**ปัญหาจริง:** ลูกค้าลืมนัดแล้วไม่มา เสียคิวทั้งช่อง · ลูกค้าเก่าหายไปเฉยๆ ไม่ได้ตามกลับ · คอร์สที่ขายไปหมดอายุโดยลูกค้าไม่ได้ใช้

**ทำได้มากกว่าแค่เตือนนัด**

- เตือนนัดล่วงหน้า 1 วัน และซ้ำอีกครั้งก่อน 2 ชั่วโมง
- **ให้ลูกค้ากดยืนยันหรือขอเลื่อนนัดผ่าน LINE ได้เลย** ลดการไม่มาตามนัดชัดเจน
- เมื่อมีคนยกเลิก → **ส่งคิวว่างให้ลูกค้าที่รออยู่ทันที** เปลี่ยนช่องว่างเป็นเงิน
- **ติดตามลูกค้าที่ไม่มาเกิน 3 เดือน แล้วส่งโปรดึงกลับอัตโนมัติ** ← ทำเงินให้ลูกค้าเห็นชัดที่สุด
- เตือนคอร์สที่ซื้อไว้ใกล้หมดอายุ ทั้งฝั่งลูกค้าและฝั่งร้าน
- สรุปรายได้และจำนวนเคสรายวัน/รายช่าง
- สต็อกเวชภัณฑ์และผลิตภัณฑ์ที่ใช้

**ดึงข้อมูลจากไหน:** ระบบนัดหมายที่ใช้อยู่ · Google Calendar · Sheet · LINE OA

**ราคาที่ควรเสนอ:** 9,900 – 19,900

> 🔒 **ข้อมูลอ่อนไหวที่สุดในเอกสารนี้** — ข้อมูลสุขภาพเป็นข้อมูลส่วนบุคคลอ่อนไหวตาม PDPA ต้องมีความยินยอมจากลูกค้าก่อนส่งข้อความ ห้ามใส่รายละเอียดการรักษาในข้อความแจ้งเตือน (เขียนแค่ "ถึงเวลานัดของคุณ" พอ) และต้องแบ่งสิทธิ์ผู้ใช้ให้ชัด

**ถามก่อนเสนอราคา**

- ใช้ระบบนัดอะไรอยู่
- มีลูกค้าในระบบกี่คน วันละกี่คิว
- ได้ขอความยินยอมส่งข้อความจากลูกค้าไว้หรือยัง
- มีขายคอร์สแบบครั้งไหม (ถ้ามี งานจะซับซ้อนขึ้น)

## 19. บริษัททั่วไป — ฟอร์มติดต่อ → เซลส์

**ปัญหาจริง:** ลูกค้ากรอกฟอร์มแล้วไม่มีใครติดต่อกลับ 2 วัน · ไม่รู้ว่า lead มาจากช่องทางไหน · เซลส์แย่งกันบ้าง ปล่อยทิ้งบ้าง

**ทำได้มากกว่าแค่ส่งเข้า Sheet**

- ฟอร์มจากทุกช่องทาง (เว็บ / Facebook / LINE) เข้า Sheet เดียวกันทันที
- แจ้งเตือนเซลส์ที่รับผิดชอบ พร้อม**แบ่งเวรอัตโนมัติ** ไม่ต้องแย่งกัน
- **เตือนหัวหน้าถ้ายังไม่มีใครติดต่อภายใน 30 นาที** ← ข้อนี้คือของจริง ลูกค้าที่ตอบช้ากว่าคู่แข่งคือลูกค้าที่เสียไปแล้ว
- ตอบกลับลูกค้าอัตโนมัติทันทีว่าได้รับเรื่องแล้ว
- ติดตามสถานะ lead: ติดต่อแล้ว / เสนอราคา / ปิดการขาย / ไม่สนใจ
- **รายงานว่า lead มาจากช่องทางไหน และปิดได้กี่เปอร์เซ็นต์** ใช้ตัดสินใจว่าควรลงโฆษณาที่ไหน
- เตือน lead ที่ค้างในสถานะเดิมนานเกินไป

**ดึงข้อมูลจากไหน:** Google Form · ฟอร์มบนเว็บลูกค้า · Facebook Lead Ads API · LINE OA webhook

**ราคาที่ควรเสนอ:** 3,900 – 9,900

> ⭐ **งานที่ขายง่ายที่สุดในเอกสารนี้** — ขอบเขตชัด ทำเสร็จเร็ว ลูกค้าเห็นผลวันแรก เหมาะใช้เป็นงานแรกเพื่อเก็บรีวิว แล้วค่อยขายงานใหญ่ตามทีหลัง

**ถามก่อนเสนอราคา**

- ฟอร์มอยู่ที่ไหนบ้าง
- มีเซลส์กี่คน ต้องแบ่งงานยังไง
- อยากให้เตือนหัวหน้าเมื่อไหร่
- ต้องการติดตามสถานะจนปิดการขายด้วยไหม (ถ้าใช่ ราคาขึ้นเป็น 9,900+)

## เช็กลิสต์คัดกรองงาน — ถามทุกครั้งก่อนเสนอราคา

ถามให้ครบ 6 ข้อนี้เสมอ ป้องกันงานพังกลางทาง

1. **ข้อมูลอยู่ที่ไหน และดึงออกมาได้ยังไง** — ถ้าตอบไม่ได้ ยังเสนอราคาไม่ได้
2. **ลูกค้ามีสิทธิ์เข้าถึงข้อมูลนั้นจริงไหม** — ถ้าต้องรออนุมัติจากแพลตฟอร์ม อย่าตกลงวันส่งมอบ
3. **มีข้อมูลส่วนบุคคลไหม** — ถ้ามี ต้องคุย PDPA และแบ่งสิทธิ์ผู้ใช้
4. **ใครเป็นคนรับการแจ้งเตือน และรับทางไหน**
5. **ปริมาณข้อมูลเท่าไหร่ อัปเดตบ่อยแค่ไหน** — มีผลกับค่าเซิร์ฟเวอร์
6. **หลังส่งมอบ ใครดูแล** — เสนอค่าดูแลรายเดือนแยกตั้งแต่ต้น อย่าปล่อยให้กลายเป็นแก้ฟรีตลอดชีพ

## สัญญาณว่าควรปฏิเสธงาน

- ต้องหลบ anti-bot, captcha หรือ bypass login
- ขอดึงข้อมูล**คู่แข่ง**จาก marketplace
- ลูกค้าไม่มีสิทธิ์เข้าถึงข้อมูลที่ขอให้ดึง
- ขอบเขตเปลี่ยนไปมาตั้งแต่ยังไม่เริ่มคุยราคา
- เร่งวันส่งมอบทั้งที่ยังไม่ได้สิทธิ์เข้าถึงระบบ
