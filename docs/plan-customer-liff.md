# แผน Phase 10 — หน้าเว็บฝั่งลูกค้า (LIFF)

**หน้าที่ลูกค้าของคลินิกเปิดจาก LINE OA เพื่อจองคิวเอง ดูนัด และดูคอร์สคงเหลือ** · ต่อจาก [plan-clinic-demo.md](plan-clinic-demo.md) · ต.ค. 2569

> **เอกสารนี้คืออะไร**: แผนลงมือทำหน้าฝั่งลูกค้าที่แผนหลักเคยเก็บไว้เป็น "ของขายเฟส 2" (plan-clinic-demo.md §2 แถว "ฝั่งลูกค้า")
> วันนี้ดึงขึ้นมาทำก่อน เพราะเป็นหน้าที่เจ้าของร้านเห็นแล้วนึกภาพออกทันทีว่าลูกค้าของเขาจะใช้อะไร
> ใช้ Next.js ตัวเดิมใน `frontend/` ไม่แยกแอปใหม่

---

## 1. หน้านี้ช่วยปิดการขายยังไง

เจ้าของคลินิกเห็นหลังร้าน (dashboard) แล้ว แต่ยังไม่เห็นหน้าร้านที่ลูกค้าของเขาจับต้อง ท่อนเดโมที่ต้องการคือ:

1. ยื่นมือถือให้เจ้าของร้าน เปิดหน้าร้านของเขาเองในแอป LINE เห็นรูปสวย บริการ ราคา ช่าง
2. ให้เขากดจองเองใน 4 แตะ: บริการ → ช่าง → เวลา → ยืนยัน
3. **คิวโผล่บนบอร์ดคิวของ dashboard บนโน้ตบุ๊กข้าง ๆ ภายในไม่กี่วินาที** ← ท่อนปิดการขาย
4. เปิดแท็บ "คอร์สของฉัน" เห็นวงแหวนครั้งคงเหลือ แล้วพูดว่า "ลูกค้าเห็นเองว่าเหลือกี่ครั้ง ไม่ต้องโทรถามร้าน"

ประโยคขาย: **"ลูกค้าจองเองตอนตีหนึ่งได้ ไม่ต้องรอแอดมินตอบแชท และคิวไม่ชนกันเพราะระบบล็อกให้"**

## 2. การตัดสินใจที่ล็อกแล้ว

| เรื่อง | เลือก | เหตุผล |
| --- | --- | --- |
| ที่อยู่ของโค้ด | **Next.js เดิม** route group ใหม่ `(customer)` ใต้ path `/c/*` | ใช้ brand token, font, build, deploy ชุดเดียวกับ dashboard |
| เปิดจากไหน | **LIFF (LINE Front-end Framework)** ขนาด Full จากริชเมนู LINE OA | ลูกค้าไม่ต้องติดตั้งแอปหรือสมัครอะไร |
| ยืนยันตัวตนลูกค้า | LIFF ส่ง **ID token** → backend ตรวจกับ LINE (`/oauth2/v2.1/verify`) → ออก **customer session JWT** แยกจาก JWT พนักงาน | ตรวจที่ขอบระบบจุดเดียว endpoint ข้างในเชื่อ `customerId` ได้เลย |
| เก็บ session | cookie httpOnly `clinicq_customer` ผ่าน route handler `/api/customer/[...path]` | แบบเดียวกับ dashboard ที่มีอยู่ (`lib/session.ts`) สคริปต์ในหน้าอ่าน token ไม่ได้ |
| ลูกค้าที่ยังไม่ผูก LINE | ลูกค้าเก่า: ใส่รหัสเชื่อม 6 หลัก (ใช้ logic เดียวกับ `linkAccount`) · ลูกค้าใหม่: สมัครด้วยชื่อ เบอร์ และติ๊ก consent 2 ช่อง | PDPA ได้หลักฐานความยินยอมแบบดิจิทัลตั้งแต่วันแรก |
| **โหมดเดโมไม่ต้องมี LINE** | เมื่อ `DEMO_MODE=true` หน้า `/c` มีปุ่ม "ดูในมุมลูกค้า" ให้เลือกลูกค้าจาก seed หรือกด "ลูกค้าใหม่" เพื่อสมัครด้วยชื่อตัวเอง | เดโมบนโน้ตบุ๊กหรือจอประชุมได้ทันที ไม่ต้องพึ่งเน็ตหรือ ngrok หน้าลูกค้า · ทางลูกค้าใหม่ให้เจ้าของร้านเห็นชื่อตัวเองขึ้นบนบอร์ดคิว (§10) |
| รูปบริการและช่าง | เพิ่มคอลัมน์ `imageUrl` ใน `Service` และ `photoUrl` ใน `Provider` | เจ้าของร้านเปลี่ยนรูปเองได้ภายหลัง เป็นจุดขายต่อ ไม่ฝังรูปในโค้ดหน้าเว็บ |
| โทนสี | ฝั่งลูกค้าใช้ **พื้นงาช้าง/ครีม + ทอง + ตัวอักษร navy** (dashboard ยังเป็น navy เข้ม) | รูปที่เตรียมมาเป็นโทนเบจอุ่นทั้งชุด พื้นครีมทำให้รูปเด่น สีทองกับ navy ยังมาจาก `shared/src/brand.ts` |
| ไลบรารีแอนิเมชัน | `motion` (Framer Motion) อย่างเดียว | ทำ carousel, การเปลี่ยนขั้นตอน และปุ่มได้ครบ โดยไม่ต้องใช้ WebGL ซึ่งหนักเกินไปสำหรับ in-app browser ของ LINE บน Android รุ่นล่าง |
| กันคิวชน | ใช้ `AppointmentsService.create` เดิม (lock ช่าง + exclusion constraint) | ไม่เขียน logic จองซ้ำ จองจาก LIFF กับจากหน้าร้านชนกันไม่ได้ |

## 5. ของตกแต่งจาก Scrolltide

Scrolltide ไม่ได้แจกโค้ด แต่ละชิ้นเป็น prompt สำหรับสมาชิกที่เสียเงิน **ตัดสินใจแล้ว (24 ต.ค. 2569): ไม่สมัคร**
ใช้ Scrolltide เป็นแค่ภาพอ้างอิงแนวทาง แล้วทำเอฟเฟกต์แนวเดียวกันขึ้นเองด้วย `motion` ไม่ลอกโค้ดหรือ prompt ของเขา หน้าตาจะใกล้เคียงแต่ไม่เหมือนเป๊ะ

ชิ้นที่ใช้เป็นแนวอ้างอิง คัดเฉพาะชิ้นที่ใช้นิ้วแตะบนมือถือได้ และไม่ใช้ WebGL:

| ใช้ที่ | ชิ้นจาก Scrolltide | เหตุผล |
| --- | --- | --- |
| Splash เปิดแอป | **Intro Loader** | เปิดมาเห็นแบรนด์ทองก่อน รู้สึกพรีเมียมตั้งแต่วินาทีแรก |
| carousel บริการ | **Spotlight Carousel** หรือ **Depth Carousel** (CSS 3D ล้วน) | ปัดด้วยนิ้วได้ รูปบริการเด่น |
| ทีมช่าง | **Morph Pill Card** | แตะแล้วขยายเป็นโปรไฟล์ช่างพร้อมปุ่ม "จองกับช่างคนนี้" |
| ขั้นตอนจอง | **Step Path** | เส้นประเชื่อม 4 ขั้น บอกว่าเหลืออีกกี่ขั้น |
| รีวิว | **Quote Deck** | การ์ดรีวิวซ้อนกันเลื่อนเอง |
| แกลเลอรีบรรยากาศร้าน | **Photo Stack** | แตะแล้วรูปบนสุดปัดออก เล่นได้ด้วยนิ้ว |
| ปุ่ม "จองคิว" หลัก | **Glow Ring Button** | ปุ่มเดียวในหน้าที่ต้องการให้คนกด ควรเด่นที่สุด |

**ไม่เลือก**: ชิ้นที่ทำงานด้วยเมาส์ชี้ (Expanded Cards, Hover List, Image Trail, Mosaic Trail) เพราะบนมือถือไม่มี hover · ชิ้นที่ใช้ WebGL หรือ GPU shader (Light Cove, Ember Carve, Liquid Carousel, Grainy Carousel) เพราะกินแบตและกระตุกใน LINE บน Android รุ่นล่าง ซึ่งเป็นเครื่องของลูกค้าคลินิกจำนวนมาก

ทุกชิ้นต้องเคารพ `prefers-reduced-motion` คือปิดแอนิเมชันเมื่อเครื่องตั้งค่าลดการเคลื่อนไหวไว้

## 6. API ฝั่งลูกค้า (ใหม่)

ทุก endpoint อยู่ใต้ `/api/customer/*` ใช้ `CustomerAuthGuard` แยกจาก `JwtAuthGuard` ของพนักงาน (endpoint ชุดนี้ติด `@Public()` เพื่อข้าม guard พนักงาน แล้วใช้ guard ลูกค้าแทน)

```
POST   /api/customer/auth/liff          { idToken } → ตรวจกับ LINE → ออก customer JWT (หรือคืน needsLink)
POST   /api/customer/auth/link          { idToken, code } ผูกบัญชีด้วยรหัส 6 หลัก
POST   /api/customer/auth/register      { idToken, name, phone, consentReminder, consentMarketing }
POST   /api/customer/auth/demo          { customerId }  ← เปิดเฉพาะ DEMO_MODE=true

GET    /api/customer/shop               ข้อมูลร้าน + บริการ (รูป ราคา เวลา) + ช่าง (รูป ตำแหน่ง) ← public ไม่ต้องล็อกอิน
GET    /api/customer/availability       ?serviceId &providerId? &date  (ใช้ AppointmentsService.availability เดิม)
GET    /api/customer/me                 ชื่อ, consent, สถานะ LINE
GET    /api/customer/appointments       นัดของตัวเองเท่านั้น
POST   /api/customer/appointments       { serviceId, providerId?, startsAt, customerCourseId? }
PATCH  /api/customer/appointments/:id/confirm | request-reschedule | cancel
GET    /api/customer/courses            คอร์สของตัวเอง + ครั้งคงเหลือ + วันหมดอายุ
```

หลักความปลอดภัย:
- `customerId` มาจาก JWT เท่านั้น ห้ามรับจาก body หรือ query
- ทุกนัดที่แก้ไขต้องตรวจว่าเป็นของลูกค้าคนนั้น ไม่ใช่ก็ตอบ 404 (ไม่ใช่ 403 เพื่อไม่บอกว่ามีนัดนั้นอยู่)
- "ช่างคนไหนก็ได้" ให้ backend เลือกช่างที่ว่างในช่องนั้น ไม่ส่งรายชื่อนัดของคนอื่นกลับไปหน้าลูกค้า
- นัดที่สร้างจาก LIFF มี `createdById = null` เหมือนนัดที่ลูกค้ากดรับคิวว่าง แล้วระบบเตือนนัดของ Phase 4 จะทำงานต่อเองโดยไม่ต้องแก้

## 7. ลำดับงาน · **3 วัน**

### วันที่ 1 — Backend ฝั่งลูกค้า

- migration เพิ่ม `Service.imageUrl` และ `Provider.photoUrl` · seed ใส่ path รูปตามตาราง §4
- สคริปต์ `frontend/scripts/prepare-demo-images.mjs` ย่อรูป แปลงเป็น WebP และตั้งชื่อใหม่ตามตาราง §4 รันซ้ำได้ ผลลัพธ์เหมือนเดิมทุกครั้ง
- โมดูล `customer-portal/`: `CustomerAuthService` (ตรวจ ID token กับ LINE, ออก JWT), `CustomerAuthGuard`, controller ตาม §6
- env ใหม่: `LINE_LIFF_CHANNEL_ID` (ตรวจ ID token), `JWT_CUSTOMER_SECRET` · เพิ่มใน `env.validation.ts`
- ดึง logic ผูกบัญชีจาก `LineWebhookService.linkAccount` ออกมาเป็นฟังก์ชันที่ใช้ร่วมกันได้ทั้งแชทและ LIFF
- test: ตรวจ ID token ไม่ผ่านตอบ 401 · ลูกค้า A แก้นัดของ B ไม่ได้ · จองช่องที่ถูกจองไปแล้วตอบ 409 · demo endpoint ปิดเมื่อ `DEMO_MODE=false`

**เสร็จเมื่อ** — `curl` ด้วย token เดโม จองคิวได้ แล้วคิวโผล่ใน `GET /api/appointments/day-board` ของพนักงาน

### วันที่ 2 — โครงหน้า + การจอง

- ติดตั้ง `@line/liff` และ `motion` · route group `(customer)` พร้อม layout ธีมครีม-ทอง + แถบเมนูล่าง
- แก้ `proxy.ts` ให้ path `/c/*` ไม่ถูกส่งไปหน้า login ของพนักงาน
- route handler `/api/customer/[...path]` (ใช้รูปแบบเดียวกับ `/api/proxy`)
- หน้า welcome, หน้าร้าน (ยังไม่ต้องมีเอฟเฟกต์), ขั้นตอนจอง 4 ขั้น, หน้าจองสำเร็จ, นัดของฉัน, คอร์สของฉัน
- ลดรอบ refetch ของบอร์ดคิวใน dashboard เหลือ 5 วินาทีขณะ `DEMO_MODE=true` ให้คิวใหม่โผล่เร็วตอนเดโม
- คิวใหม่ที่เพิ่งเข้าบอร์ดมีขอบทองกะพริบ 3 วินาที คนดูคลิปจะรู้ทันทีว่าคิวไหนเพิ่งมา ไม่ต้องไล่หาเอง
- `pnpm demo:reset` รีเซ็ตข้อมูลกลับเป็น seed และคืนนาฬิกาเป็นเวลาจริง ใช้ก่อนอัดทุกเทคและก่อนเข้าพบลูกค้า (ตอนนี้มีแค่ `reset-clock` ยังไม่มีตัวรีเซ็ตข้อมูล)

**เสร็จเมื่อ** — เปิดโหมดเดโมบน Chrome มือถือจำลอง จองครบ 4 ขั้น แล้วบอร์ดคิวบนอีกแท็บขึ้นคิวใหม่

### วันที่ 3 — ตกแต่ง + ต่อ LINE จริง

- ใส่ชิ้นตกแต่งตาม §5 ทีละชิ้น ทุกชิ้นต้องลื่นบนมือถือก่อนไปชิ้นถัดไป
- สร้าง LIFF app ใน LINE Developers Console (Full size, scope `openid profile`) · endpoint URL ชี้ ngrok ระหว่างพัฒนา (LIFF บังคับ HTTPS)
- เพิ่มริชเมนู LINE OA 3 ปุ่ม: จองคิว · นัดของฉัน · คอร์สของฉัน
- ปุ่ม "จองคิวเลย" ใน Flex เตือนคอร์สใกล้หมดอายุและแคมเปญดึงลูกค้ากลับ เปลี่ยนให้ลิงก์เข้า LIFF ตรง ๆ ← ข้อความที่ส่งอยู่แล้วกลายเป็นยอดจองทันที
- Lighthouse บนมือถือ: Performance ≥ 85 และไม่มีรูปไหนเกิน 250KB

**เสร็จเมื่อ** — 🏁 เปิดริชเมนูใน LINE บนมือถือจริง จองคิวได้ คิวโผล่บน dashboard และอีก 1 วันก่อนนัด (กดข้ามเวลาด้วย Time Machine) ได้ข้อความเตือนพร้อมปุ่มยืนยัน

## 10. อัดคลิปและเดโมตอนเจอลูกค้า

คลิปกับเดโมสดใช้คนละงาน **คลิปส่งไปก่อนนัด** ให้เจ้าของร้านยอมนัดเจอ **เดโมสดใช้ตอนเจอ** ให้เขาลองกดเอง แล้วเก็บคลิปไว้ในมือถือเป็นตัวสำรองเผื่อเน็ตที่ร้านล่ม

### 10.1 คลิป (60–75 วินาที)

**จัดภาพ**: แบ่งจอในเทคเดียว ซ้ายเป็นหน้าลูกค้าใน Chrome โหมดมือถือ (390×844) ขวาเป็นบอร์ดคิวของ dashboard
ท่อน "จองแล้วคิวโผล่" **ห้ามตัดต่อตรงกลาง** ต้องเห็นต่อเนื่องในช็อตเดียว คนดูจึงเชื่อว่าระบบทำงานจริง ไม่ได้ตัดต่อหลอก

| วินาที | ภาพ | ซับไตเติล |
| --- | --- | --- |
| 0–4 | หน้าร้านเต็มจอ ปุ่มจองคิวเรืองแสง | "ลูกค้าจองคิวเองได้ตอนตีหนึ่ง โดยไม่ต้องรอแอดมินตอบแชท" |
| 4–15 | เลื่อนหน้าร้าน ผ่านบริการ ช่าง และรีวิว | "หน้าร้านของคุณอยู่ใน LINE ลูกค้าไม่ต้องโหลดแอป" |
| 15–35 | จองคิว 4 แตะ คือเลือกบริการ ช่าง เวลา แล้วยืนยัน | "แสดงเฉพาะเวลาที่ว่างจริง จองชนกันไม่ได้" |
| 35–45 | กล้องเลื่อนไปทางขวา คิวใหม่ขึ้นบนบอร์ดพร้อมขอบทอง | "คิวเข้าบอร์ดหน้าร้านทันที" |
| 45–55 | แท็บคอร์ส วงแหวนบอกครั้งที่เหลือ | "ลูกค้าเห็นเองว่าคอร์สเหลือกี่ครั้ง ไม่ต้องโทรถามร้าน" |
| 55–65 | ข้อความเตือนนัดใน LINE พร้อมปุ่มยืนยัน (อัดจากมือถือจริงหนึ่งช็อต) | "ระบบเตือนก่อนนัด 1 วัน ลดลูกค้าลืมนัด" |
| 65–75 | การ์ดปิดท้าย ชื่อ ช่องทางติดต่อ ช่วงราคา | "ทดลองดูกับร้านของคุณ ทักมาได้เลย" |

#### ตั้งค่าก่อนอัด

- รัน `pnpm demo:reset` ก่อนทุกเทค
- เลือกลูกค้าที่มีคอร์สใกล้หมดอายุ วงแหวนกับป้ายเตือนจะขึ้นในภาพ
- ใช้หน้าต่าง incognito ซ่อนแถบบุ๊กมาร์ก ตั้งซูมเบราว์เซอร์ให้ตัวหนังสืออ่านออกบนมือถือ
- อัดด้วย OBS ที่ 1080p 30fps แล้วใช้ ffmpeg (มีในเครื่องแล้ว) ตัดหัวท้ายและบีบไฟล์ให้ส่งใน LINE ได้
- **ฝังซับไตเติลลงในวิดีโอ** เพราะเจ้าของร้านส่วนใหญ่เปิดดูแบบปิดเสียง ใส่เพลงเบา ๆ ได้ แต่ไม่ต้องพากย์
- ทำสองขนาด แนวนอน 16:9 สำหรับ Facebook และแนวตั้ง 9:16 (เอาเฉพาะจอมือถือ) สำหรับส่งใน LINE หรือทำ Reels

### 10.2 เดโมสดตอนเจอ

1. **ให้เจ้าของร้านถือมือถือเอง** แล้ววางโน้ตบุ๊กที่เปิดบอร์ดคิวไว้ตรงหน้าเขา
2. ให้เขากด "ลูกค้าใหม่" แล้วสมัครด้วย**ชื่อตัวเอง** จากนั้นจองคิว
3. รอให้ชื่อเขาขึ้นบนบอร์ดคิว นี่คือช่วงที่เงียบได้ ปล่อยให้เขาเห็นเอง ไม่ต้องอธิบายซ้อน
4. กด Time Machine ข้ามไปหนึ่งวันก่อนนัด ให้เขาเห็นว่าข้อความเตือนจะขึ้นแบบไหน
5. ปิดด้วยหน้าวัดผลแคมเปญดึงลูกค้ากลับ (Phase 7) เปลี่ยนเรื่องจาก "ระบบสวย" เป็น "ระบบหาเงินคืนให้"

**ให้มือถือเปิดหน้าลูกค้าได้**: วิธีที่ชัวร์ที่สุดคือ deploy ขึ้นออนไลน์ตาม Phase 8 แล้วเปิดลิงก์จริง ถ้ายังไม่ได้ deploy ให้รัน `next dev -H 0.0.0.0` แล้วต่อมือถือกับโน้ตบุ๊กผ่านฮอตสปอตเดียวกัน
